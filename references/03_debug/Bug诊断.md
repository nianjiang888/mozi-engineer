# Bug 诊断

> 你的目标不是修这个 bug，而是**不让同样的 bug 第二次出现**。

## 七步诊断法

1. **看用户视角**：他们看到的报错信息是什么（截图/复现路径）？
2. **看系统视角**：监控曲线、日志、trace 哪一段先崩？
3. **画时序**：请求-响应时序里每个节点的状态快照。
4. **最小复现**：能写到测试里复现吗？不能就别动。
5. **假设 + 实验**：每次只改一处验证一个假设，别一次改三处。
6. **锁根因**：把根因写下来，不是症状。
7. **加测试**：bug 修完前先写测试，看是否重现；合上 PR 看回归。

## Bug 的常见"假根因"

- "重启就好了" → 没找到根因
- "网络抖动" → 真的吗？看了 log 吗？
- "清缓存就行" → cache 也是代码里的，看为什么没失效
- "并发问题" → 真的吗？栈帧里有 race 吗？
- "这个老 bug 一直有" → 不修的债 ≠ 不存在

## 定位问题的工具箱

| 现象 | 工具 |
|---|---|
| 服务挂了/超时 | 看 trace、pprof、日志关键字 |
| 数据不对 | 数据库 binlog、行级 diff 工具、A/B 阶段输出比对 |
| 接口报错 5xx | trace + 关联 metric + 上下游日志 |
| 偶发 | 上 canary + 加大采样 |
| 性能变差 | bench + pprof 火焰图，对比两个版本 |

## 关键 Bug 模式速查

### 类型/空值
- NullPointer / TypeError: `null` 流过；空集合返回；optional 处理路径漏
- IndexError: 边界条件；空数组；非法索引

### 并发
- Race condition: 共享变量没锁；channel buffer 边界
- 死锁: 锁顺序不一致；超时未设
- 资源耗尽: 连接池、goroutine、句柄

### IO
- 网络抖动：连接未设 timeout；重试不幂等
- 数据库慢：慢 SQL；锁等待；大事务
- 缓存穿透/雪崩/击穿：缓存层缺保护

### 时间/时区
- 夏令时跳变
- UTC vs 本地时间混用
- 时区格式化不一致

### 配置/版本
- 配置文件 key 变了
- 依赖升级 breaking change
- 环境变量在不同环境语义不同

## 复现 ⇨ 修复 ⇨ 回归

```
复现: 写一个能稳定失败的测试
原因: 锁根因（带行号/链接）
修复: 让测试先红后绿
回归: 跑全部测试 + 性能基线
```

## 反模式

- "在线 hotfix 一下生产先稳住" → 不修测试的 hotfix 必返场
- "试个别的方案说不定好" → 假设 + 验证，别玄学
- "不修问题把症状修了" → 缓存层报错被吃 → 三天后雪崩
- "复现不出来先放着" → 放久的偶发 bug 必成 P0
