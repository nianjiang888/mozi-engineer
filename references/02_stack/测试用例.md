# 测试用例

> 测试不是为了覆盖率指标，是为了**生产逼你要改时能不慌**。

## 测试金字塔（按成本/价值）

| 层 | 数量级 | 价值 | 工具 |
|---|---|---|---|
| 单元 | 千级 | 高 | pytest/Jest/vitest/go test |
| 集成 | 百级 | 中 | testcontainers/postman/DbUnit |
| 端到端 | 十级 | 高（贵）| playwright/cypress/k6 |
| 探索/灰度 | 滚动级 | 最高 | canary/SLO/线上抽样 |

**永远不要倒过来**（e2e 多、单测少）：金字塔倒过来 = 慢且脆。

## 测试要测的（按优先级）

1. **边界**：0、1、最大、`null`、空集、超长字符串、超大数值
2. **错误路径**：依赖挂了、参数非法、限流触发、配额用尽、token 过期
3. **状态机**：初始/中间/终态/非法跃迁
4. **关键业务**：钱、权、风控、A/B test 切换
5. **happy path 兜底**：不能让 happy path 漏掉

## 好的测试名字长这样

```
test_pay_with_locked_account_throws_402_not_retryable()  ✓
test_pay()  ✗
test_basic_case()  ✗
```

测试名 = 行为文档。一行名能告诉你这个分支在防什么。

## TDD 三步走（红/绿/重构）

1. **红**：先写期望行为（让测试失败）
2. **绿**：写能通过的最短代码
3. **重构**：在测试保护下清理代码

TDD 的关键不是教条，**是测试存在**——后写的也行，但**先写测试 = 设计先于实现**。

## Mock 的边界

- ✅ Mock 外部依赖（DB/Redis/HTTP）/ 时间 / 随机
- ❌ 不要 mock 自己写的核心逻辑——那是伪测试
- 不写 mockable 单测 = 集成测试替，但**慢**

## 性能基准测试（bench）

- 改"热路径"代码前先跑一遍 bench 取基线
- 改完再跑一遍，差异 > 5% 写 PR 描述里说明
- 同环境、同 commit、同参数；避免噪音

## 反模式

- "覆盖率 90% 但全是 happy path" → 形同裸奔
- "测试依赖外部服务" → CI 慢且不可重现
- "测的是实现细节" → 重构一次测试全红，可测性差
- "一个测试方法 30 行" → 拆；一个测试一个断言
